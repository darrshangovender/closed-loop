### Shield decisions with no allowed command

The shield's proof assumes that every command it issues is in the set its table allows. At a decision where that set is empty the runtime has nothing safe to issue and falls back to the first command in the table's priority order; for the pump pair that is `STOP|STOP`, so both pumps stay stopped each quarter and a repair cannot progress in that episode. An empty set arises only after the abstract model's assumptions are already violated. The fallback is a known limit of the shield and is left as it is; this table counts how often it was used, as `k/n` episodes with any such decision and the total number of decisions. ## Limitations carried into every report

- Everything here is synthetic data from a simulated plant, built by one author.
- The F1 plant shares its structure with the estimator and the planner's world model.
- F1 timings and several plant parameters are assumptions, not measurements of a real plant.
- The abstraction is a proof about a model; the conformance gap above is a measured, non-zero distance between that model and the simulated plant on sampled traces.
- F2 samples are small, so F2 can separate only very large effects.
- The falsification search scores spec robustness (`evaluate_theta`), so it cannot find an event that only the plant records; plant-only events are counted in M-VIOL and shown apart in C-SHIELD, but no search looks for them.

Proof scope: see `docs/PROOF-SCOPE.md`.
